# nanos world - Version 1.40.0

- **Release Date:** 2023-03-09 11:41:11 UTC
- **Raw Timestamp:** `2023-03-09T11:41:11.252Z`

---

🆕 **New Features**
- New **Widget** class! Now you can spawn Widgets on client side to build UIs from Unreal native UMG system! Spawn custom UserWidgets as well Native ones through scripting! Build them dynamically without needing to touch Unreal! https://docs.nanos.world/docs/next/scripting-reference/classes/widget
- Added new method to **Client**: `GetConnectedServerIP()`.
- Added new **music** to Main Menu!
- The **Downloading/Loading** system was completely reimplemented from scratch. Fixing a bunch of errors and problems from the old system (such as server fatal errors, players stuck while downloading and etc). This new system integrates properly and fixes some other display problems on the Loading Screen too (such as flickering status). The downloading time should be WAY faster now when connecting to a server.

⏫ **Improvements**
- Now Blueprint Parameters support passing **WebUI** and **Widget** as parameters (receives as UserWidget on Blueprint) and also Textures from SpecialPath!
- The enum `WebUIVisibility` was renamed to `WidgetVisibility` (the old one got deprecated - with warnings!).
- The **Loading Screen** and it's progress display was slightly changed. Now it will display the total amount of data being downloaded while joining a server (including server files and assets from vault).
- Added new settings to Debug Settings tab: **Max HTTP files** being downloading simultaneously - the default value is 8 (experimental).
- Now servers have **Compression Level** on 1 by default. Which will compress most of the package files when sending to clients by default. Set it to 0 in Config.toml to disable it.
- We added a bunch of validators to circumvent some downloading problems which will kick the player from the server if something goes wrong while downloading files. Note: there is a known "issue" when server tries to send files with more than 256 MB to players in P2P mode (using the sockets networking system), causing the Fatal errors to show up in the server and the player to do not receive the file. Now the player will be kicked if the server tried to send it. This is due a limitation of the server networking buffer when sending a lot of data to clients. In a near future we will look into a solution for this.

🔨 **Bug Fixes**
- Fixed new Trace methods without debug drawing.
- Fixed Loading Screen popup errors on P2P servers.
- Fixed an invalid Package.toml or Assets.toml causing no item from Vault from appearing on menu.
- Fixed error when trying to send a destroyed entity through Server events. Now it will show a warning and the entity will be nullified instead.
- Fixed some wrong logs.
